# RemoteDeck 用户指南（简体中文）

[English](user-guide.en.md) · [返回 README](../README.md) · [下载 Release](https://github.com/shilittle/RemoteDeck/releases)

## 1. 安装前检查

RemoteDeck 支持 Windows 10/11 x64，本地应用已包含 Electron/Node 运行时。远端目标应为运行 OpenSSH Server 的 Linux；监控需要 `python3`，GPU 与 btop 功能会按远端能力显式降级。

从 GitHub Release 下载 NSIS 安装器或 portable EXE，然后计算 SHA-256，并与 Release 说明逐字核对：

```powershell
Get-FileHash .\RemoteDeck-*-win-x64-setup.exe -Algorithm SHA256
```

RemoteDeck v1.x 官方资产当前不提供代码签名，可能触发 SmartScreen“未知发布者”警告。请只从本仓库的 Release 页面下载，不要把第三方镜像中的同名文件视为官方构建。

## 2. 安装与首次启动

- NSIS 安装器：按当前用户安装，可选择目录并创建开始菜单/桌面快捷方式。
- Portable：直接运行单个 EXE；“portable”仅指无需安装，配置仍保存在当前 Windows 用户的应用数据目录。

首次引导提供两条真实路径：

- 添加一台新主机。
- 迁移 LabPulse SSH v0.1.0：只读取你通过系统对话框选择的 `config.json`，先显示预览再导入，相同文件不会重复导入；旧清理命令以禁用状态保留。

## 3. 添加主机与认证

在“主机”中填写别名、主机名/IP、端口、用户名和可选工作目录。认证方式包括：

- 密码：每次需要时输入，只驻留内存。
- 键盘交互：服务端问题在连接对话中回答，只驻留内存。
- 私钥：通过系统文件选择器选取；加密私钥口令只驻留内存。
- Windows OpenSSH agent：使用当前用户 agent 中的密钥。

可选跳板机只支持一层 ProxyJump，跳板机和目标机分别验证主机密钥与认证。

首次连接会显示算法、SHA-256 指纹和目标地址。请通过服务端控制台、管理员或另一条可信渠道核对后接受。已信任主机的密钥发生变化时，RemoteDeck 会硬失败并显示新旧指纹；不要直接接受变化，应先调查，再手动移除旧记录。

“部署公钥”会：

1. 读取所选公钥材料。
2. 使用应用拥有的临时文件原子更新远端 `authorized_keys`。
3. 按密钥材料去重。
4. 用新密钥建立一条全新连接验证。
5. 仅在验证成功后切换默认认证方式。

## 4. 终端

连接主机后进入“终端”并新建标签。每个标签对应真实 SSH PTY，支持 bash、vim、tmux、btop、Unicode/IME、窗口尺寸同步、滚屏搜索、Ctrl+C 和文本剪贴板。

- 关闭普通 PTY 会结束对应远端 shell，无法恢复其进程。
- 长期任务请使用 tmux/screen；Codex 工作流可使用 RemoteDeck 管理的稳定 tmux 会话。
- 链接只允许 HTTP(S)，打开前仍应检查目标。
- 自由终端输入不经过命令风险分类器；L0/L1/L2 只约束命令库和 Codex 固定操作。

常用快捷键：

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+1…7` | 切换活动区 |
| `Ctrl+Shift+T` | 新建终端 |
| `Ctrl+J` | 打开任务中心 |
| `Ctrl+,` | 打开设置 |

## 5. 文件与传输

“文件”工作区使用 SFTP，不通过 shell 拼接路径。它支持：

- 显示隐藏文件、新建文件夹/空文件、重命名和删除。
- 拖放或文件选择器上传，选择本地目录下载。
- 递归目录传输、跳过/覆盖/重命名冲突策略。
- 大文件字节进度、速度、取消和失败重试。

递归操作使用 `lstat`，不会跟随符号链接。上传/下载先写应用实例和任务拥有的临时文件，成功后再重命名；取消只清理该任务拥有的精确路径。

## 6. SSH 隧道

可保存 LocalForward 或 RemoteForward。每条活动隧道使用独立 SSH 连接，不会占用终端，支持 TCP/HTTP 健康检查、失败退避和网络恢复。

- 普通端口冲突不会终止占用端口的其他进程。
- Clash/Mihomo 探测只读；多个候选时必须自行选择。
- 从旧版导入的远端清理命令默认禁用，并显示完整高风险警告；只有恢复流程中一次性显式授权后才可能运行。

## 7. 监控、btop 与进程

监控把随包 Python collector 通过已认证 SSH channel 的 stdin 发送给远端 `python3 -u -`，不会安装远端文件。JSONL 数据在主进程中执行大小限制和严格 schema 校验。

- 没有 `python3`、GPU 工具或 btop 时会显示明确降级，不会伪造数据。
- btop watchdog 只管理 RemoteDeck 创建的会话，不解析或记录 btop 屏幕内容。
- 只能向最新快照中属于当前 SSH 用户、且通过新鲜 `ps` 查询再次匹配的进程发送信号。
- SIGKILL 必须先对同一进程执行近期 SIGTERM，再进行二次确认。

## 8. 命令库与 Codex

命令预设可设为全局或主机专属。主进程在执行前重新读取最终命令并计算实际风险：

- L0：只读白名单命令，可直接运行。
- L1：显示完整目标与命令，要求确认。
- L2：除 L1 外，还要求输入主机别名或指定确认文字。

声明风险只能提高，不能降低主进程判定。PTY 命令进入普通终端；非 PTY 命令在任务中心显示有界输出并可取消。

Codex 面板只执行固定能力探测和当前安装版本公开支持的稳定 CLI 命令。安装计划显示官方脚本并要求确认；登录使用设备认证或 SSH PTY。RemoteDeck 不读取 `~/.codex/auth.json`、不接收 token、不解析 TUI 字节，也不添加绕过 sandbox 的参数。

## 9. 托盘、退出与登录启动

默认关闭窗口只会隐藏到托盘，主进程继续维护 SSH、传输、监控和隧道。只有托盘“完全退出”或系统退出流程才释放所有应用拥有的资源。

设置中可以：

- 禁用托盘常驻。
- 启用 Windows 登录后启动。
- 选择登录启动时隐藏窗口。

## 10. 诊断与隐私

“导出诊断包”通过系统保存对话框生成 ZIP，包含：

- 应用版本与运行能力。
- 脱敏设置摘要和匿名化 profile 统计。
- 最多 5 个、每个最多 512 KiB 的最近分类日志。

诊断包不包含终端/SFTP 内容、端点标识、密码、私钥、口令或 Codex token；写盘前还会执行第二次秘密扫描。提交给维护者前仍应自行检查 ZIP 内容。

## 11. 故障排查

1. 查看主机、隧道和任务中心中的明确状态与错误。
2. 不要绕过主机密钥变化；先从服务端控制台核对新指纹。
3. 确认远端 OpenSSH、`python3` 与目标端口可用。
4. 对下载损坏或来源不明问题运行 `Get-FileHash`，并与 Release 说明中的 SHA-256 核对。
5. 导出并人工检查诊断包后，再通过 GitHub Issue 提交。
6. 查阅[已知限制](known-limitations.md)与对应功能文档。

## 12. 卸载

NSIS 版可从 Windows“已安装的应用”卸载。默认不删除用户数据，避免意外丢失主机配置；如需清除，请先导出需要的信息，再由当前用户手动删除 RemoteDeck 应用数据目录。Portable EXE 本身可直接删除，但它使用的用户数据目录不会自动删除。
