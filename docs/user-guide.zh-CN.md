# RemoteDeck 2 中文用户指南

## 安装与校验

RemoteDeck 2 支持 Windows 10/11 x64。请先在“可选功能”中启用 Windows OpenSSH Client，并确认目标 Linux 运行 OpenSSH Server。

RemoteDeck 2 正式制品发布后，从本仓库 GitHub Release 下载 `RemoteDeck-<版本>-win-x64-setup.exe` 和 `SHA256SUMS.txt`，然后执行：

```powershell
Get-FileHash .\RemoteDeck-2.0.0-win-x64-setup.exe -Algorithm SHA256
```

结果必须与发布文件逐字一致。仓库当前未配置 Authenticode 签名；应以正式制品记录的签名状态为准，未签名安装器可能触发 SmartScreen 未知发布者提示。安装器配置为按当前用户安装；系统缺少 WebView2 时会启动微软下载引导程序。发布前请查看[未勾选的发布清单](release-checklist.md)与[待填写制品记录](release-manifest.md)，不要把本指南当作安装包已经生成的证明。

## 第一次连接

1. 在“主机”中新建配置，填写别名、地址、端口、用户名、认证方式与默认工作目录。也可以安全导入 OpenSSH config 中明确的普通 `Host` 项。
2. 点击“扫描密钥”。通过服务器控制台、管理员或其他独立可信渠道核对 SHA-256 指纹。
3. 只在完全一致时接受。若以后密钥变化，RemoteDeck 会硬阻断；确认服务器确实更换密钥后，先显式移除旧信任，再扫描和核验。
4. 打开“终端”并新建标签。密码、键盘交互和私钥口令直接输入终端，不会写入应用配置。

“测试连接”、SFTP、隧道、监控和后台命令使用非交互 OpenSSH。它们需要未加密且权限正确的专用密钥、已解锁私钥或 ssh-agent；仅密码配置应先在终端中使用，并部署公钥后再启用后台功能。

## 工作区

### 主机与密钥

- 支持搜索、分组、基于已保存直连主机的 ProxyJump、超时、保活、压缩、`IdentitiesOnly` 和默认目录。请先确认跳板指纹，再通过跳板扫描并独立核验目标指纹。
- 可生成 Ed25519 密钥、查看发现的私钥并向已验证主机部署公钥。
- 导入 OpenSSH config 不跟随 `Include`，也不导入通配符、`Match` 或未知指令。
- 用作其他已保存主机 ProxyJump 的主机不能直接删除，必须先移除引用。其余删除会先禁止新的 SFTP、终端和命令工作，取消并等待这些自有任务，再阻止新的仓库连接并清理隧道、遥测与已跟踪 btop；只有清理成功后才持久化删除主机及其隧道/命令预设。

### 终端

- 每个标签是真实的 `ssh.exe` + ConPTY 会话；可并行打开、双击重命名、搜索滚屏、复制、粘贴、调整窗口和新建 shell 重连。
- Unicode 11 与中文 IME 由 xterm.js/浏览器组合输入处理。`Ctrl+C` 会发送给远端程序。
- 键盘输入通过仅绑定 IPv4 本机回环、带短期单次票据并绑定来源/会话代际的 WebSocket 进入 ConPTY，不作为 Tauri invoke 参数；重连、关闭、删除主机或退出会使旧通道失效。
- 关闭标签只终止该标签拥有的 SSH 子进程。关闭应用窗口到托盘不会中断会话；托盘“退出”会执行完整清理。

### 文件与传输

- 浏览远端目录，创建、重命名和删除文件/目录；目录删除是递归操作并要求确认。
- 通过“选文件”“选目录”或将本地路径拖入窗口上传；选择远端条目和本地目录后下载。
- 冲突策略包括询问、覆盖、跳过和自动改名。任务中心显示进度，可取消和重试。
- 覆盖不会先删除原目标：完整结果先写入自有临时路径，原目标移到自有备份后再发布；发布失败会回滚，回滚也失败时会保留并报告备份路径。
- 重试会重新读取当前保存的主机/ProxyJump 配置并重新校验任务，而不是复用失败尝试中的旧连接字段。
- 取消只清理 RemoteDeck 当前任务创建且带有效 UUID 标记的临时文件。根路径、遍历、下载 basename 逃逸、超大目录树和模糊危险路径会被拒绝。删除主机会退役新 SFTP 工作并等待直接操作与传输事务结束；活跃传输依赖的目标或跳板连接字段必须先停止传输才能修改。

### 隧道

- LocalForward：本地监听端口转发到远端可达目标。
- RemoteForward：远端监听端口转发到本机可达目标；外部可达性取决于服务器 `GatewayPorts`。
- 每条隧道有独立 SSH 子进程、自动启动、异常恢复、退避、修订序健康状态和有界日志。每次重连都会读取当前保存的主机配置；活跃隧道依赖的目标或跳板连接字段必须先停止隧道才能修改。停止或删除只影响该条隧道。

### 监控

- 结构化监控将内置 Python 脚本通过 stdin 发送给远端 `python3 -u -`，不在远端安装文件。
- 主机中的“应用启动时自动监控”只控制启动时自动采集；关闭后仍可手动启动。后台采集使用 BatchMode，不会弹出密码或私钥口令提示。每次重连会读取当前保存的主机配置；活跃采集器或已跟踪 btop 所依赖的目标/跳板连接字段必须先停止相关工作才能修改。
- 显示 CPU、负载、内存、交换区、网络、磁盘、NVIDIA GPU 和进程；历史仅保存在内存，同时受设置值、每主机 3,600 条/16 MiB 和全局 8,192 条/64 MiB 的较小值限制。
- 每条进程记录包含 `/proc` 启动时钟。TERM/KILL 会把主机、PID、启动时钟、用户和命令作为同一身份在远端原子复验；KILL 只在该精确身份最近成功收到 TERM 后开放，并再次显示原生“是/否”警告。
- “随启动时自动监控启用 btop watchdog”只作用于自动监控主机。watchdog 需要远端 `btop`、`tmux` 和 `timeout`，重启计数来自远端 tmux；缺失工具会明确显示，不影响结构化监控。
- btop 所有权来自应用数据中的稳定安装级 nonce，同一安装在后续“启动 btop”（含随应用启动）时可接管相同标记的远端会话，其他或无标记会话会被拒绝。新会话若 30 秒内未设置精确标记会自行退出。显式停止、删除主机和正常退出只清理本进程已创建或同安装接管并再次核验标记的会话；遥测/btop 清理最多等待 10 秒，整个退出最多等待 12 秒，网络故障后可能需下次先启动接管、再停止。

### 命令与 AI Agent

- 一次性命令和预设在执行前由 Rust 重新分类。L0 为只读；L1 会修改状态并要求目标确认；L2 为删除、提权、重启、信号等高风险命令，必须输入精确确认文本。
- 输出和并发有上限；交互命令自动交给普通 SSH PTY。取消只终止该任务拥有的子进程。
- 支持 Codex、Claude Code、Gemini CLI 和 OpenCode 的探测、安装、登录、启动、恢复与更新。安装/更新会显示确认，凭据和设备登录仍由各官方 CLI 管理。
- RemoteDeck 不添加 `--yolo`、自动批准或沙箱绕过参数。

## 设置、迁移与诊断

- 可设置终端字体、遥测周期/保留、默认下载目录（可手输或使用原生目录选择器）、默认 Agent、托盘行为和登录启动。
- “迁移”先只读预览 LabPulse SSH v0.1.0 或 RemoteDeck v1 数据；可分别选择主机、隧道、命令和设置。整批数据只写一次，失败不会留下部分导入，来源哈希防止重复导入，旧主机信任永远不导入。
- 诊断 ZIP 默认写入“下载”，包含脱敏状态、能力和主机指纹。密码、密钥、Token、终端内容和远端命令输出不会收集。

## 快捷键与卸载

- `Ctrl+1` 至 `Ctrl+7`：切换七个工作区。
- `Ctrl+Shift+T`：新建终端。
- `Ctrl+J`：任务中心。
- `Ctrl+,`：设置。

在 Windows“已安装的应用”中卸载。为防误删，用户状态默认保留；需要彻底移除时，先导出所需数据，再由当前用户手动删除 RemoteDeck 应用数据目录。
